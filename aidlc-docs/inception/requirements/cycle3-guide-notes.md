# Cycle 3 Guide Notes - 검수 가이드 정리 (2026-09-28)

출처: `guide/guide.md`(사용자 메모 10항), `guide/KakaoTalk_20260915_111627341.png`, `guide/KakaoTalk_20260916_202748544.png`, PDF "13. 생활 및 거주환경 기반 VQA_검수가이드_0911"(텍스트 추출본. 이후 파일이 DRM 형식(.ggpdf, SECD 헤더)으로 바뀌어 이미지 슬라이드는 읽지 못함: 검수 가이드라인 6~7·11쪽, 오류 예시 12·15쪽, 불가 예시 16~23쪽).

## A. 데이터 구조 (PDF 8~10쪽)
- 지시문(Instruction): Archetype = 현재 어떤 상황인지, Persona = 데이터를 사용하는 사람, Task = 어떤 질문·답변을 만들어야 하는지
- CoT: 1단계 이미지 속 장소·상황 파악, 2단계 위험·주의점 확인, 3단계 상황에 맞는 행동과 답변 정리
- QA 1~6: 점진적이고 자연스러운 질문·답변으로 수정
- "작업 생성이 아닌 검수 작업. 검수자가 되었다는 가정하에 검수 후 오류는 수정"

## B. 검수 포인트 (guide.md 4항)
- B-1 **Facts 가 가장 중요**. 이미지와 일치해야 함. 예: 컵인데 화분이라 함(X), 흰색 차인데 파란색(X), 하나인데 여러 개(X) → 사실에 맞게 수정
- B-2 **Task 와 QA 의 방향 일치**. 예: Task 는 "길을 안내" 인데 QA 1~4 는 물건을 찾음 → 불가 제출

## C. 수정 vs 불가 (guide.md 3, 5항)
- 오류가 있는 부분 → 수정 후 제출 / 불가에 해당 → 불가 제출
- **수정 사항이 많아 작업 시간이 길어지면 무리하게 수정하지 말고 불가로 제출**

## D. 아키타입·태스크 정정 (guide.md 2, 7항 + 스크린샷 1)
- 카테고리가 가전(가구)인데 이미지에 가전이 안 보임 → 가전조작 자체가 불가는 아니고, **조작부가 보이지 않을 때 불가**
- 스크린샷 1: Archetype 이 "음식"인데 QA 가 쇼핑(김·멸치를 찾음) 내용이면 **Archetype 을 쇼핑으로, Task 를 쇼핑 템플릿으로 변경** 필요 (검토자가 Instruction 을 고친다는 뜻)

## E. QA 멀티턴 정리 (guide.md 10항 + 스크린샷 2)
- QA 의 멀티턴이 CoT 3단계보다 더 많은 추론을 하면(예: 화면에 없는 "어른이 왔어" 턴) 그 턴을 삭제하고 앞 턴의 답변에 합쳐 작성. **QA 는 CoT 3단계와 내용이 맞아야 함**
- "멀티턴이 쓸데없이 길어지면 줄여서 작성해도 됨" → 턴 삭제·병합 허용(증가는 언급 없음)

## F. 텍스트 정리 (guide.md 1, 8, 9항)
- 문맥에 맞지 않는 단어 삭제 (예: 광장 앞의 "포장")
- **전화번호가 보이면 삭제** (예: 234-5678)
- 어린이 데이터셋: QA 가 너무 딱딱하면 반려 대상은 아니지만 가능한 선에서 부드럽게 수정

## G. 연관 QA 목록 (guide.md 6항)
- 왼쪽 연관 QA 목록은 참고만, 오른쪽 작성 내용을 기준으로 검수 (현재 프롬프트와 일치)

## H. 현재 도구와의 차이
| 가이드 | 현재 도구 | 필요한 변경 |
|---|---|---|
| D: Archetype·Task 정정 | Instruction 은 모델이 수정하지 않음(경고만, FR-3.3) | 정정 제안 허용 여부 결정 |
| B-2/C/D: 불가 조건 3종 | 정합성 점수 ≤ 40 만 불가 후보 | 규칙 기반 불가 후보 추가 |
| E: 턴 삭제·병합 | 턴 수 불변(BR-22) | 감소 허용 여부 결정 |
| F: 전화번호·불필요 단어·어린이 문체 | 없음 | 프롬프트 규칙 + 전화번호 결정론 검사 |
| A: CoT 단계 정의 | 프롬프트에 없음 | judge/revise 프롬프트에 정의 추가 |
