## 2. 기능 요구사항

### FR-C5-1. 복합 방향 표현 정리 (피드백 1)
- "앞 왼쪽", "앞 오른쪽", "뒤 왼쪽", "왼쪽 앞" 처럼 두 방향을 붙인 표현은 사진에서 더 중요한 한 방향("앞쪽" 또는 "왼쪽")으로 고친다
- 도구가 정규식으로 결정론 검출(`(앞|뒤)\s?(왼|오른)쪽`, `(왼|오른)쪽\s?(앞|뒤)쪽?`)해 text_issues(kind="direction")로 넣고 수정 필요로 처리. 모델도 같은 종류를 보고할 수 있다
- revise 규칙: 판정에 direction 항목이 있으면 사진을 보고 한 방향을 택해 바꾼다. 의미가 달라지면 문장을 최소로 다듬는다

### FR-C5-2. 횡단보도 도움 요청 (피드백 2, 보행안전·어린이)
- 대화가 "어른에게 도와달라고 해" 처럼 주변 사람의 도움을 권하는 경우, **사진에 그 사람(어른 등)이 실제로 보일 때만** 허용
- 보이지 않으면 해당 턴은 consistent=false(note: "사진에 없는 어른에게 도움 요청")로 판정하고, revise 는 "보행자 신호가 초록불이 되면 건너가, 차가 오는지 잘 살핀 후 안전하게 건너가" 처럼 스스로 안전하게 건너는 안내로 바꾼다
- 사이클 4 의 unsafe_guidance(무단횡단)와 구분: 횡단보도·신호가 있는 곳에서 신호를 확인하고 건너라는 안내는 안전 안내이다. 횡단보도가 없는 도로를 건너라는 것만 위험 권고

### FR-C5-3. 가전조작은 가구 포함 (피드백 3)
- 가전조작 아키타입은 가전뿐 아니라 **가구**(서랍·문·손잡이가 있는 수납장·옷장·책상 등)도 대상이다
- appliance_controls_visible: 가전 또는 가구의 조작부(손잡이·문·서랍·버튼·표시등·틈)가 보이면 true
- archetype_fits_environment / archetype_suggestion: 사진에 가전이 없고 가구만 있어도 조작부가 보이면 가전조작은 적합. 불가·정정 제안을 내지 않는다
- 판정·수정 프롬프트의 가전조작 설명과 템플릿 참고 문구에 "가구 포함" 명시(템플릿 문장 자체는 LabelOn 고정값이므로 변경하지 않음)

### FR-C5-4. 일상지원 템플릿 변경 (피드백 4, Q1=D)
- 새 템플릿: "(Persona) 이 주변에서 가려는 곳과 필요한 것을 찾아갈 수 있도록 주변 시설과 길이 어떻게 이어져 있는지 확인하고, 어느 쪽으로 가야 하는지와 걸리는 것을 우선 안내하세요."
- `archetype_templates.일상지원` 을 새 문장으로 바꾼다(기본값, config.example.yaml, config.yaml). 아키타입 정정으로 Task 를 생성할 때도 새 문장 사용
- 서버에는 옛 문장으로 만든 초안이 남아 있을 수 있으므로 `legacy_archetype_templates: {일상지원: [옛 문장]}` 로 템플릿 일치 검사에서 옛 문장도 일치로 인정한다(경고 없음)
- 새 문장은 길·방향 안내를 포함해 실외에서도 적용 가능 → 사이클 4 의 환경 충돌 예시에서 "실외 도로에 일상지원" 을 제거한다(가이드 불가 예시 5 는 옛 템플릿 기준). 실내탐색·음식·쇼핑의 실외 충돌은 유지

## 3. 인수 기준
- AC-C5-1 초안에 "앞 왼쪽" 이 있으면 text_issues 에 direction 항목이 생기고 수정 필요, 화면 목록에 "방향" 라벨
- AC-C5-2 (프롬프트 규칙, 실제 건 확인) 사진에 어른이 없는데 도움 요청 턴이 있으면 불일치 판정·수정
- AC-C5-3 (프롬프트 규칙, 실제 건 확인) 가전조작 + 손잡이 있는 가구 사진에서 불가·정정 제안 없음
- AC-C5-4 옛 일상지원 문장의 초안도 템플릿 일치로 판정되고, 정정 시 생성되는 Task 는 새 문장이다
- AC-C5-5 기존 111개 테스트 유지
